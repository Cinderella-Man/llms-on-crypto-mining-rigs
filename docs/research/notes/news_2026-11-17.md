# What is new since 2026-11-03 for the three models, the engine and other forks (2026-11-17)

Miner Llama v4.0 shipped on 2026-11-16 on upstream llama.cpp b12360, and v5 starts with a merge of upstream's newest
tag. This note lists what the makers of the three models, upstream llama.cpp, other forks and engines, and NVIDIA
published after [the last sweep](flash_next_news_2026-11.md) (2026-11-03, Flash-Next only) that changes v5's order of
work on the P106 rig (nine 6 GB cards, compute 6.1, PCIe 1.0 x1, a 4 GB host).

Sources were read on 2026-11-16 and 2026-11-17: GitHub pull requests, issues, tags and commit lists, Hugging Face
model listings, cards and commit histories, and NVIDIA's driver and toolkit archives. Nothing was run, built or
downloaded. Every figure below is its source's own report on its own hardware; none was measured on a P106, so each is
a claim to test here. Numbers marked **est.** are my arithmetic. Registry ids (Q…) refer to
[quants/experiments.md](../../../quants/experiments.md).

## Summary

1. **Nothing found moves the top of v5's order.** Measuring v4.0 first and the race across two rigs stay where they
   are. The sweep adds seven rows and changes nine; it closes none.
2. **Flint and Ornith-1.5-122B have published drafters, and no note here knew them.** Inco AI's DFlash2 for Flint
   (GGUF, 240 to 811 MB) and for Ornith (1.86 GB) are dated 2026-10-26 and 2026-10-19: before the last sweep, which
   covered one model. The maker reports 4.23 to 4.53 accepted tokens of 7 on reasoning and code for Flint and 6.37 to
   9.20 of 15 for Ornith, on full-precision targets. Ornith's card names a trap for every GGUF target: the drafter's
   mask-token row is stored as zeros and acceptance about halves.
3. **Upstream's replay of recurrent state is not merged.** [#31669](https://github.com/ggml-org/llama.cpp/pull/31669)
   is open and active (six backends done, last push 2026-11-16). The merge of b12445 does not bring it, and I would
   not write the fork's own version (Q686) while it is this close.
4. **The merge is more than a tag bump.** Between b12360 and b12445 upstream rewrote the server's slot scheduling and
   prefix matching (b12411), split the DFlash speculation code into four methods (b12377) and refactored the warp
   primitives in 20 CUDA files (b12414). A fix for the new scheduler on recurrent models is still open.
5. **A fusion can stop matching after such a merge with every test green.** A P100 patch set lost 19.7 % of its MoE
   decode that way on b12211 and found it only in a matcher trace. The merge needs a count of launches a token.
6. **Three upstream items touch compute 6.1 directly:** an open change that switches the quantized gate and up fusion
   off on all Pascal cards, an open fix for the one-token `MUL_MAT_ID` bug this project wrote up on 2026-11-05, and a
   report of silent wrong answers at about 60,000 tokens on a P100 with hybrid models.
7. **Pascal support is intact.** b12445 still builds compute 6.1 code for toolkits below 13 and ships CUDA 12.8 and
   12.4 binaries. No issue or pull request proposes dropping CUDA 12 or compute 6.1.
8. **The makers of Flint and Ornith published nothing since October.** Swift's maker added one Flash-Next tier that
   does not fit the rig. Unsloth documented the n-gram table swap. Qwen's template change leaves the text unchanged.
9. **The driver line has nothing new since the last sweep.** Its newest release, 580.196.07, is dated 2026-10-07;
   CUDA 12.9.2 is still the last 12.x.

### 2.4 Does anything drop CUDA 12 or compute 6.1

No. At b12445 `ggml-cuda`'s build file still adds `50-virtual`, `61-virtual` and `70-virtual` for toolkits below
13, and differs from b12360 only by one added architecture for a Blackwell card
([#30099](https://github.com/ggml-org/llama.cpp/pull/30099)). The release carries Linux CUDA 12.8 and Windows CUDA
12.4 builds beside CUDA 13.5. A search of issues and pull requests updated since 2026-11-03 for Pascal, CUDA 12 and
compute capability found only the items above. v1.0.0 removed 35 deprecated functions and `--defrag-thold` from the
public API; v4.0 already sits on it.

## 4. The NVIDIA driver and CUDA lines that support Pascal

- **Driver.** The newest release of branch 580, the last that supports Pascal, is 580.196.07; its installer in
  [NVIDIA's archive](https://download.nvidia.com/XFree86/Linux-x86_64/) is dated 2026-10-07. The rig runs 580.178.04
  (dated 2026-07-13, [hardware spec](../../mining_rig.md)). One
  [report](https://www.comss.ru/page.php?id=22530) lists two fixes in it, resume after hibernation and a black
  screen on console switches under kernel 7.0 and newer; neither is a compute change. Nothing is newer than the last
  sweep, and I would not change the rig's driver for it. Whether any 580 release differs for compute is Q1532.
- **CUDA.** [The toolkit archive](https://developer.nvidia.com/cuda-toolkit-archive) lists 12.9.2 (May 2026) as the
  newest 12.x, which is what the rig has, and 13.5.0 (November 2026) as the newest overall. Compute 6.1 left the
  toolkit with 13.0. Upstream's CI moved its CUDA 13 builds to 13.5 on 2026-11-06 and kept the 12.x builds.
- **The P100 report of section 2.3 is the same on two driver branches,** so it is not a driver fault.
