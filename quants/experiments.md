# Quant experiments

Every experiment in the quants subproject, planned or done, so that nothing is run twice. Check this page before
starting anything; add a row before an experiment starts and fill it in when it ends. Results are summarized here and
written up in [README.md](README.md) or [research.md](research.md); raw logs are kept outside the repository.

## Plan

**Quality bar (decided 2026-10-23):** a Flint file counts only if it is within noise of Unsloth's UD-Q4_K_XL against
BF16 (KLD 0.120, 87.7 % same top token, perplexity +3.9 %; in practice KLD ≲ 0.125 and same top token ≳ 87.5 %).
People use Unsloth's quants, and nobody trades ~9 points of token agreement for speed, so files at the makers' Q4_1
level (78–80 %: makers-fast, S1, S2, the Q4_0 variants) are no longer release candidates or targets. Speed claims compare
against UD-Q4_K_XL on the same build and cards. Engine and kernel work still counts wherever it is measured, because it
speeds up every file.

**Now (2026-10-23, 20:00):** both machines run overnight queues while four code tasks run in parallel. Rig (since 19:37,
one job at a time, ~10–11 h): Q19 stage 1 (verify cost of 1–8 tokens with the kernels on and off, a 4-token profile,
real-server verify steps, draft rounds with a random 32k EAGLE-3 head), Q65, Q54 (attention at depth on 6 and 9 cards,
f16 and q8_0 KV), Q68, Q55, Qwen3.6 MTP on the fork (Q43), then Q75 (Q58 again with the makers' settings). Quant
machine (since 19:40): the BF16 GGUF rebuilt, then Q73's re-priced mixes on one GPU set and Q62's KV-cache KLD on the
V100s. Code: Q70/Q71 (task harnesses the makers' way), Q76 (FP32 activation sums), Q50 (shared-expert fusion, with a
design for Q37), Q64 (offline n-gram replay); Q74 on a CPU. The makers' engine rec
([note](../docs/research/notes/rec_engine.md)) is Apple-only, has no speculative decoding and confirms that Flint has no
MTP head; it sets Q41's sampling and history protocol and puts the makers' Q4_1 back among Q41's candidates (Q74). Keep
this line current: say what is running, where, and since when.

Every speed figure for the new files is still a prediction ([token_cost.py](../scripts/token_cost.py)); step 1 measures
them, and the steps after it depend on what it shows.
